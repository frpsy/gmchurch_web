## 감사성찬례 순서 (출처: `worship.eucharistOrder`, 주보 3면과 대응)
1. **개회예식**(입당 포함): 입당 성가, 죄의 고백과 용서.
2. **말씀의 전례**: 구약·시편 화답송·서신서 봉독 → 복음환호송 → 복음 봉독·설교 → 니케아 신경(또는 사도신경) → 교회와 세상을 위한 중보기도.
3. **성찬의 전례**: 평화의 인사 → 봉헌(빵·포도주·헌금) → 성찬기도(축성) → 주님의 기도 → **영성체**.

## 예배 슬라이드 (출처: `data/worship-order.json`, `presentation/worship/`, 2026-10-25·26)
주보 3면 예배 순서에서 웹 슬라이드(브라우저 전체화면)를 만든다. 조작: ←/→·스페이스·클릭·쓸기, `F` 전체화면, `B` 빈 화면, `O` 목차, 주소 `#번호`로 해당 슬라이드, `?date=YYYYMMDD`로 주 선택(기본은 최신). 글꼴은 원티드 산스 가변(jsDelivr, OFL 1.1, 안 되면 Pretendard·시스템 글꼴).
- **요청(2026-10-26, 교우 여정훈(사도) 의견)**: 현장 매체는 둘이다. ① 지금 위치와 회중이 응답할 말을 알려주는 화면(`presentation/worship/`), ② 예배 전체 순서와 악보를 담은 예식문(`presentation/worship/book.html`). 성경을 읽는 사람이나 기도를 이끄는 사람의 인격에 눈이 가야 하므로 **슬라이드에는 예배 주제 그림, 회중이 응답할 말, 노래 가사, 현재 위치 막대만 둔다.** 독서 본문·사제 기도문·설교 내용은 싣지 않는다.
- **예식문**(`book.html`, `?date=YYYYMMDD`): 주보 순서 그대로 번호·`†`(일어섬)·맡은 이·기도서 쪽·성가 번호를 싣고, 회중 응답은 `사제`/`독서자`/`회중` 글자로 구분해 굵게 보인다(`†`가 주보에서는 일어섬이라 기호 대신 글자를 썼다). 독서 본문은 싣지 않고 책·장절과 응답만 둔다(본문 포함 여부는 교회 결정). 악보는 `score` 이미지로 싣는다: 2026-10-25 성시 90편 악보는 주보 3면 이미지에서 잘라 썼고(해상도 낮음), 성가집 곡은 악보 파일이 없어 번호만 표시된다. A4 인쇄 가능(인쇄 버튼). 생성은 슬라이드와 같은 `build-worship-slides.js`가 `data/worship/YYYYMMDD.book.json`으로 한다.
- 기준은 교회가 쓴 슬라이드(TalkFile_20260927·20261004·20261018.pptx, 사용자 제공)다. 검은 바탕·흰 글자, 맨 앞 안내 3장(환영·반려동물석·성찬 안내), 위치 막대 칸이 바뀔 때마다 주제 그림 슬라이드, 설교 슬라이드는 주제 그림 위에 `설교: 이름`.
- **PPTX 내려받기**: 슬라이드 화면 위쪽의 `PPTX` 버튼이 지금 보이는 슬라이드 전체(그 주 안내 그림 포함)를 16:9 PowerPoint 파일(`예배슬라이드-YYYYMMDD.pptx`)로 만든다. 브라우저 안에서 PptxGenJS(jsDelivr)로 만들며 코드는 `presentation/worship/pptx-export.js`. 인터넷이 불안한 예배 현장에서 파일로 쓰기 위한 것이다. 글꼴은 `Malgun Gothic`(기기에 없으면 PowerPoint가 대체)이고 글자 크기는 화면과 같은 비율로 어림해 맞췄다. 목차·점프·빈 화면 같은 화면 기능은 PowerPoint에서 쓰는 방식을 따른다.
- **안내(광고) 슬라이드**: 맨 앞 안내는 `worship-order.json`의 `defaults.announcements`(매주 같은 안내)와 `weeks.<날짜>.announcements`(그 주 안내)로 정한다. 항목은 글자만, 그림 위에 글자(`pos` lt·rt·lb·rb·c, `size` m·l·xl), 글자가 이미 든 그림(`alt`에 그 글자) 중 하나다. 그림은 `images/worship/notices/`에 둔다. 사진과 글자로 그림을 만드는 도구는 `presentation/worship/announce.html`(사진은 브라우저 안에서만 처리, 1920×1080 JPG로 내려받기). **바로 올리기**: 도구가 정해 주는 이름(`예배날짜-순서.jpg`, 예 `20261101-1.jpg`)으로 `images/worship/notices/`에 GitHub 웹에서 끌어다 올리면(도구의 "GitHub에 올리기 열기", 쓰기 권한 계정 필요) 설정 없이 그 날짜 슬라이드의 맨 앞 안내 바로 뒤에 나타난다(뷰어가 번호가 끊길 때까지 찾는다, 최대 12장). 지난 주 파일은 자동으로 지워지지 않는다. 반려동물석 안내는 교회가 쓰던 그림을 그대로 쓴다.
- **위치 막대**: 아래에 `모임 | 말씀 | 응답 | 파송` 네 칸, 지금 칸이 흰 바탕. 응답 칸에는 위에 작은 막대 `예물 준비 | 성찬기도 | 성체 나눔 | 영성체`가 예물 기도부터 영성체 초대까지 뜬다. 칸 나눔은 교회 슬라이드 기준이라 주보 구역과 다르다: 모임 = 입당성가·정심기도·(죄의 고백)·송가, 말씀 = 본기도·독서·시편·층계성가·복음·설교, 응답 = 신경·교회와 세상을 위한 기도·평화의 인사·봉헌~영성체 후 기도, 파송 = 축복기도·파송·교회소식·파송성가.
- 데이터 흐름: `worship-order.json`(항목마다 `stage`·`sub`·`extra`) + `worship-texts/hymns.json`(가사 있는 성가만) + `bcp.json`(기도서 쪽 → 응답 슬라이드) + `responses.json`(독서 후 응답 등 이름 붙은 응답) → `scripts/build-worship-slides.js` → `data/worship/YYYYMMDD.json`(+`index.json`). 글자·표기는 교회 슬라이드에서 옮겼고 `source`에 슬라이드 번호를 적었다.
- 줄 표시: `†` 사제가 먼저 하는 말(흐리게), `○` 독서자(흐리게), `◎` 회중 응답(크고 밝게). 기호는 교회 슬라이드를 따르되 `◉◎`는 `◎` 하나로 줄였다.
- **성가집**: 대한성공회 성가집(성가개편위원회, 2013~2014 표기)을 교우가 공개한 `dulkuka12.github.io/khymn/hymnbook.pdf`('성가 2015')를 가리킨다. 스캔 그림이라 글자 추출이 안 되고 OCR 정확도도 낮아, 저장소에는 악보·가사를 복사하지 않고 `hymns.json`의 `pdfPage`(PDF 쪽, 성가 번호와 다름)로 예식문에서 링크한다(2026-10-26 확인: 258→253쪽, 89→97, 369→357, 76→83, 82→90, 65→73, 83→91, 208→203, 272→266, 500→483). 가사·악보를 직접 올리는 것은 곡마다 저작권 표기가 있어(예: 369 Stainer & Bell) 허락 확인 전에는 하지 않는다.
- 성가집 곡은 가사 없이 `성가 N장` 번호와 제목만 띄운다(교회 슬라이드도 그래 왔다). 가사가 있는 성가 82(거룩하시다)·65(주의기도)·83(하느님의 어린양)만 슬라이드 글자를 싣는다. 성가집 파일을 받으면 `hymns.json`에 가사를 넣는다.
- `extra: true` 항목은 주보에 인쇄되지 않지만 교회 슬라이드 세 주에 늘 들어간 순서다(예물 기도, 성찬기도 영광송, 영성체 초대, 파송). 10-18 주처럼 어린이 형식으로 바뀐 주는 다르다.
- 교회와 세상을 위한 기도의 회중 응답은 주마다 달라(`선하신 주여, 우리의 기도를 들어주소서.` 등) 주보에 없으므로 `refrain`에 입력하기 전에는 제목만 뜬다.
- 성경 본문 추출(`scripts/extract-bible.js`, `data/worship-texts/readings.json`)은 슬라이드에는 쓰지 않으며 예식문용으로 남겨 뒀다. PDF 글자와 bible.anglican.kr 공동번역을 대조하며, PDF 전체 추출은 1분 넘게 걸려 임시 폴더에 캐시한다.
- 악보 보관(2026-10-27 사용자 요청): `data/hymnal-2015/`에 온라인 성가 2015 원본 PDF의 634쪽 전체를 재압축 없는 JPG로 저장했다. `index.json`은 성가 번호 → 이미지 경로 배열, `INDEX.md`와 `hymns/번호.md`는 사람이 찾는 목록이다. 원본 색인은 657개 항목이며 96–100번이 없다. 전체 PDF 페이지는 보관했고 이 번호의 매핑은 추측하지 않았다. 상세는 `data/hymnal-2015/README.md`.
- 악보 이미지는 가사 OCR 데이터가 아니다. 기존 가사·슬라이드 생성 흐름은 그대로이며, 악보가 필요하면 보관 색인의 `images`를 참조한다. 성가집·기도서의 슬라이드 사용·전자 배포 허락 범위는 별도 확인 사항으로 남아 있다.
