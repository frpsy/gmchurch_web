# 성공회 광명교회 모바일 주보 운영 규칙

기존에 확정한 제작 원칙과 최근 요청사항(2026-11-05, 사용자 지시)을 통합한 기준이다. `CLAUDE.md`의 6-1 항목 하위 규칙과 함께 적용하며, 충돌하면 이 문서의 최신 기준을 따른다.

## 0. 모바일 주보와 홈페이지 주보 게시판의 구분 (2026-11-05 사용자 확정)

두 페이지는 서로 다른 페이지이며 서로 대체하거나 같은 페이지로 취급하지 않는다.

| 구분 | 모바일 주보 (`jubo/`) | 홈페이지 주보 게시판 (`bulletin.html`) |
|---|---|---|
| 형태 | 예배 순서에 따라 읽는 웹 주보 | 주보 이미지 게시물 |
| 내용 | 예식문·회중 응답·성가·성경 본문 전문 | 해당 주일 주보 이미지 |
| 등록 | 모바일 주보 제작 및 배포 | 주보 이미지 별도 등록(`bulletins/`, `sync-bulletins.js`) |
| 완료 보고 | 모바일 주보 링크 제공 | 게시판 반영 여부 보고 |

- 모바일 주보를 완성하고 개발·공식 주소에 반영한다.
- 주보 이미지는 공식 홈페이지의 별도 주보 게시판에 등록한다(개발·공식 두 저장소).
- 두 페이지는 독립적으로 운영하되 날짜와 내용의 일치 여부를 검수한다.
- 모바일 주보 기본 주소(`/jubo/`)는 개발·공식 양쪽 모두 최신 주보를 표시한다.
- 교회 밴드에는 자동 업로드하지 않는다(링크 안내는 사용자가 직접 한다).
- 개발·공식은 동일한 주보 데이터(`data/jubo/`)를 사용한다. 한 번 제작·등록하면 두 홈페이지에 반영되도록 운영한다.
- 날짜별 과거 주보를 조회하더라도 기본 주소의 최신 주보 표시 기능은 유지한다.
- 보관: 홈페이지 주보 게시판은 최근 8개 주보만 유지한다(2026-11-05 사용자 확정). 넘긴 주보의 이미지·PDF·교회소식·핵심구절은 `sync-bulletins.js`가 삭제하며, 영구 보존하지 않는다. 기간(56일) 제한은 없고 개수(8개)만 적용한다(`sync-bulletins.js`, `CLAUDE.md` 주보 등록 절차 8번).
- 홈페이지 주보 게시판에는 이미지가 잘리지 않고 선명하게 표시되는지 확인하고, 게시물 날짜는 해당 주일 기준으로 한다. 모바일 주보 페이지에 일반 주보 이미지를 대신 게시하지 않는다.

## 1. 기본 운영 원칙

| 항목 | 규칙 |
|---|---|
| 대상 | 성공회 광명교회 주일예배 |
| 제작 주기 | 매주 주일예배 |
| 주보 형태 | 모바일 우선 웹 주보 |
| 기준 저장소 | `frpsy/gmchurch_web` (공식 저장소 `lmkhkm/GMSKH_Homepage`에도 반영) |
| 주보 주소 | 개발: `https://frpsy.github.io/gmchurch_web/jubo/` · 공식: `https://gmskh.or.kr/jubo/` |
| 날짜별 주소 | 개발: `https://frpsy.github.io/gmchurch_web/jubo/?date=YYYYMMDD` · 공식: `https://gmskh.or.kr/jubo/?date=YYYYMMDD` |
| 배포 원칙 | 고정 URL 유지, 최신 주보 표시. **URL은 개발·공식 홈페이지 양쪽에 배포하는 것이 기준** (공식은 머지 후 최대 2시간) |
| 공유 | 교회 밴드에서 링크·QR 코드 활용 (QR 코드는 공식 기본 주소 `https://gmskh.or.kr/jubo/` 사용) |
| 외부 게시 | 홈페이지 주보(`bulletin.html`)는 항상 게시한다. 모바일 주보는 홈페이지·외부에 게시·홍보하지 않고 링크만 사용자에게 전달한다(본문·메뉴·푸터·사이트맵에도 연결하지 않음) |
| 검색 노출 | 검색엔진 색인 제외 요청 유지 (`noindex`) |

주의: 고정 URL이 공개 GitHub Pages·공개 홈페이지에 있으므로 링크를 아는 사람은 접근할 수 있다. 검색 제외 설정만으로 비공개가 보장되지는 않는다.

## 2. 주보 제작 규칙

- 예식문: 대한성공회 예식에 맞는 순서와 문구를 정확히 수록한다.
- 회중 응답: 사제와 회중의 응답을 빠짐없이 표시하고 명확하게 구분한다.
- 성가: 성공회 찬송가 단성판을 기준 판본으로 사용한다(없는 곡만 전체판). 성가 번호·제목·악보 이미지가 일치해야 한다.
- 설교 말씀: 해당 주일 성경 본문을 축약하지 않고 전문 수록한다. 본문 출처와 판본을 확인한다.
- 교회 정보: 주교·성직자 등은 공식 홈페이지(`data.js`)의 최신 정보를 기준으로 한다.
- 파일 관리: 성가 이미지 파일명은 영문으로 관리하고, 주보에는 성가명과 번호를 표시한다.

## 3. 모바일 디자인 규칙

- 고령층 우선: 충분한 글자 크기와 대비, 읽기 쉬운 행간
- 한 화면 중심: 불필요한 새 창 이동 최소화
- 간결한 조작: 버튼과 메뉴를 최소화하고 예배 순서대로 읽기
- 일관된 디자인: 기존 교회 홈페이지의 녹색 계열 디자인 유지
- 반응형: 아이폰·안드로이드·PC에서 내용이 잘리거나 겹치지 않도록 구성
- QR 코드: 고정 주소를 사용하여 매주 재발급하지 않도록 관리
- 아이폰 점검 기준(2026-11-05): 상단 고정은 탭 줄(61px)만 두고 제목 줄은 스크롤과 함께 올린다. 하단 여백은 `main.wrap`에 96px 이상 둔다(`main{}`만 쓰면 `.wrap`의 padding 줄임 표기에 덮여 0이 된다). 누르는 영역은 44px 이상, 계좌번호 등 숫자는 줄바꿈하지 않는다(`.nw`). 주소에는 복사 버튼을 두지 않는다(계좌만). 예배 시간이 같으면 한 칸으로 합치고, 순서 이름과 같은 부제는 숨긴다. 교회소식의 `-`로 시작하는 줄은 점 목록으로 보인다. 다크 모드의 이번 주 말씀 카드는 어두운 초록(`--verse-bg`)을 쓴다.
- 2차 점검 기준(2026-11-05): 「기도문·말씀 펼치기」는 성가 악보 항목(`data-hymn`)을 제외하고 펼친다(악보까지 열면 페이지가 너무 길어진다). 글자 크기 버튼은 현재 단계를 글로 보여 준다. 맨 위로 버튼은 표지가 화면 밖으로 나가면 나타나며 관찰자로만 제어한다(부드러운 스크롤 금지). 하단 여백은 이 버튼과 출처 줄이 겹치지 않게 152px로 둔다. 출처 문구는 0.9rem·진한 색, 성가 배지는 테두리형으로 가볍게 둔다.

## 4. 제작·배포·검수 절차

1. 자료 확보 — 해당 주일 예식문, 성가, 성경 본문, 교회 소식
2. 주보 제작 — 기존 구조를 유지하면서 해당 주 자료 반영
3. 내용 검증 — 원본 대조, 누락·오탈자·판본 확인
4. 모바일 검수 — 고령층 가독성, 링크, 이미지, 화면 이동 확인
5. 배포 — 제작·검수를 마치면 별도 승인 없이 개발·공식 두 저장소에 반영하고 병합 완료까지 확인한다(2026-11-05 사용자 확정: 주보는 항상 홈페이지에 적용, 모바일 주보는 만들어 링크만 사용자에게 전달)
6. 최종 확인 — 개발·공식 양쪽 실제 공개 URL에서 최신 주보 표시 여부 확인 (공식은 반영 지연 시 미완료로 명시)

### 최종 완료 보고 항목 (2026-11-05, 다른 AI 지침과 통합)

1. 해당 주일 날짜
2. 공식 모바일 주보 기본 주소 `https://gmskh.or.kr/jubo/`(항상 최신 주보, 우선 제공)
3. 개발 모바일 주보 기본 주소 `https://frpsy.github.io/gmchurch_web/jubo/`
   - 날짜별(`?date=`) 링크는 사용자가 특정 날짜 주보를 요청할 때만 제공한다. QR 코드는 이미 제작되어 있으므로 재제작하지 않는다(2026-11-05 사용자 확정).
4. 홈페이지 주보 게시판 반영 결과 및 확인된 게시물 링크
5. 검수 결과와 남은 문제

실제 접속 및 배포 확인 없이 완료라고 보고하지 않는다. 배포·게시 권한이 없으면 임의로 완료 처리하지 않고 미완료 사항을 보고한다.

## 5. 검수 규칙 (요청 시에만)

정기 자동 검수 예약은 두지 않는다(2026-11-05 사용자 결정: 일요일 오전 8시 예약 불필요, 비활성화됨). 검수는 `주보검수`를 요청할 때만 수행한다. 해당 주 자료를 기준으로 주보와 예배 슬라이드를 대조한다. 대상은 모바일 주보의 최신 날짜, 개발·공식 내용 일치, 예식문과 회중 응답, 단성판 성가 이미지, 설교 말씀 성경 본문 전문, 예배 슬라이드와 주보 내용 일치, 고령층 사용 편의성, 홈페이지 주보 게시판 이미지 게시 상태다.

보고서는 세 가지로 구분한다.

- 확인된 문제: 실제 자료에서 발견한 누락·불일치
- 추가 확인: 원본이나 슬라이드에 접근하지 못해 검증할 수 없는 항목
- 최종 판정: 정상 / 수정 필요 / 검증 불충분

검수에서는 게시·업로드·수정·배포를 수행하지 않고 보고만 한다.

## 6. 명령어 및 완료 기준

- `주보제작` — 해당 주일 자료를 확인하고 모바일 주보 제작·검수·배포(개발·공식)까지 진행한 뒤 기본 주소 링크 두 개(개발·공식)를 사용자에게 준다.
- `주보검수` — 현재 주보와 슬라이드만 점검하고 문제점을 보고한다.
- 완료 기준: 내용 정확성, 단성판 일치, 모바일 사용성, 최신 URL 확인(개발·공식)을 모두 충족해야 한다. 자료가 부족하면 완료로 판정하지 않는다.

가장 중요한 원칙은 예배 내용의 정확성 → 고령층 사용 편의성 → 검증 후 배포 순서이며, 검수(`주보검수`)와 제작·배포 작업을 분리하는 것이다.
