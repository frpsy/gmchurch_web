# 주보 등록 절차 (홈페이지 주보 게시판·예배 슬라이드·모바일 주보)

> AGENTS.md에서 옮긴 상세 절차다(2026-11-07 지침 정리, 내용 변경 없음). 운영 원칙·완료 보고·요청어는 [`mobile-bulletin-rules.md`](mobile-bulletin-rules.md)가 우선한다.

## 매주 절차

> **표준(`data/lectionary-year-a.json`·`lectionary-year-b.json` — 연도별 파일을 날짜순으로 이어 붙임)이 기본, 주보 기록(`data/lectionary-overrides.json`)이 그 위에 덮인다.** 교회는 주마다 연속(A)/짝(B) 트랙을 오가고(RCL은 트랙에 따라 제1독서·시편이 다름), 맥추감사주일 같은 특별 주일은 표준에 없는 독서를 쓴다. **손으로 만질 곳은 overrides 하나뿐** — 나머지(특별 주일명, `worship.currentReadings`/`nextReadings` fallback)는 sync가 자동 파생한다.
>
> **추측 금지 — 주보 예배 순서면에 인쇄된 값만 기록한다.**
>
> **작업 시작 전 위키 먼저** — 주보를 읽기 전에 `docs/wiki/church.md`(사람·직함)와 `docs/church-glossary.md`를 읽는다. **사람 이름·세례명은 이미지에서 읽은 글자를 그대로 믿지 말고** 위키·`data.js`(`clergy`·`officers`)와 대조해 맞춘다(2026-10-25 `민숙희`를 `민속희`로 잘못 읽은 사례). 위키·`data.js`에 없는 이름(평신도 봉독자·봉헌자 등)은 읽은 대로 적고 완료 보고에 `미확인`으로 알린다.
>
> **자동 처리 원칙** — 사용자가 주보 이미지를 올리면(또는 `bulletins/`에 이미지가 push되면) 확인을 묻지 말고 아래 1~7을 끝까지 진행한다. 주보 예배 순서면과 4면 '교회소식'을 이미지에서 직접 읽어 `lectionary-overrides.json`·`bulletin-news.json`·`bulletin-verses.json`을 작성하고, 아래 **교회소식 검수 기준**으로 스스로 검수한 뒤 PR을 만들어 머지한다. 검수에서 고친 내용과 불확실한 부분(흐려서 읽기 어려운 글자 등)만 완료 보고에 짧게 적는다.

> **세트 규칙 (2026-11-01, 사용자 지시)** — 주보가 올라오면 **홈페이지 게시(아래 1~8, 6의 예배 슬라이드·6-1 모바일 주보 포함 + 개발·공식 두 저장소 머지)와 주보 내용 정리(순서·봉사자·교회소식을 텍스트로 정리해 사용자에게 보냄)를 항상 한 세트로** 처리한다. 둘 중 하나만 하거나 "어떤 작업을 할까요?" 하고 되묻지 않는다.
>
> **모바일 주보 링크 (2026-11-01, 사용자 지시)** — 주보 작업을 마치면 항상 모바일 주보(6-1)까지 만들어 두고, 완료 보고에 **링크 `https://frpsy.github.io/gmchurch_web/jubo/`** 를 함께 준다(사용자가 확인한다). 머지 후 반영까지 1~2분이 걸린다고 한 줄 덧붙인다. 이 경우 아래 "머지했습니다 한 줄" 보고 규칙에 링크 한 줄만 더한다.

1. 이미지 복사: `bulletins/YYYYMMDD_N.jpg` (표지부터 순서대로)
2. **예배 순서면(주 본문·성시) 확인** → `data/lectionary-overrides.json`에 그 주 항목 추가
   - 제1독서가 창세기·출애굽기 등 연속 서사면 `"track": "A"`, 예언서 등 복음과 짝이면 `"track": "B"`
   - **트랙 A일 때 주보 성시가 표준과 다르면** `"psalm": "시편 N편"` 추가 (표준 단일 시편은 트랙 B값이라 A에선 어긋남)
   - 특별 주일(맥추감사 등)은 `koreanName` + `readings`(네 본문 전체) 지정
   - 주보가 시편 대신 층계성가를 부르면 시편 생략 가능(표준 지정 시편이 그대로 표시됨)
3. **주보 4면 '교회소식' 란** → `data/bulletin-news.json`의 `weeks`에 그 주 항목 추가 (`{ title, body }`, 줄바꿈은 `\n`). 인쇄된 문구만 옮기되(띄어쓰기·약어 표기만 교정, 약어는 `G.F.S.`처럼 점으로 구분) 통계·헌금 명단 등 개인 이름 나열란은 옮기지 않는다
   - 교회소식은 4면 '교회소식' 란의 **항목(■ 제목) 하나가 `{ title, body }` 하나**다. 제목은 ■ 뒤의 문구, 본문은 그 아래 문장이며 `일시 :`·`장소 :`·`일정 :`·`말씀 :` 줄은 줄바꿈(`\n`)으로 이어 적는다(사이트가 항목표로 렌더).
4. **핵심구절** → `data/bulletin-verses.json`의 `weeks`에 그 주 항목 추가 (`{ ref, text }`). 주보에 핵심구절이 인쇄돼 있으면 그것을, 없으면 그 주 본문 말씀(주로 복음)에서 중심이 되는 1~3절을 직접 골라 알린다(되묻지 않는다). 본문은 `bible/`의 공동번역 PDF에서 `pdftotext -layout`으로 뽑아 **글자를 대조해 그대로** 옮기고(요약·변형 금지), `text`에는 절 번호·각주 기호·줄바꿈을 넣지 않는다(출처는 `ref`에 `마태 22:37-40` 형식으로). 주보에 다른 번역이 인쇄돼 있으면 인쇄된 문구를 따른다. 주보 페이지 맨 위 '이번 주 말씀' 카드와 각 주보 펼침 영역에 표시된다
5. `node scripts/sync-bulletins.js` 실행 → PDF 생성 + data.js 자동 갱신
   - 끝에 **⚠️ 트랙 미기록 / ℹ️ 시편 미기록 / ℹ️ 교회소식 미기록 / ℹ️ 핵심구절 미기록** 경고가 뜨면 해당 주 기록을 보완
6. **예배 슬라이드** → 3면 예배 순서를 `data/worship-order.json`의 `weeks`에 그 주 항목으로 옮긴다(주보에 인쇄된 값만, 항목 앞 `†`는 `stand`, 오른쪽 칸은 `by` 그대로, 위치 막대 칸 `stage`·`sub`은 지난 주 항목을 따른다). 슬라이드에는 주제 그림·회중 응답·가사·위치 막대만 들어가며 독서 본문·사제 기도문은 싣지 않는다. 새 기도서 쪽·성가 가사는 `data/worship-texts/`에 추가하고(교회 슬라이드에서 옮기고 `source` 기록) `node scripts/build-worship-slides.js`로 슬라이드(`data/worship/YYYYMMDD.json`)와 예식문(`YYYYMMDD.book.json`)을 만든다. 성시 악보는 주보 3면 이미지에서 잘라 `data/worship/scores/`에 두고 `score`로 연결한다. 그 주에 따로 알릴 안내(광고)는 사용자가 `announce.html`로 만든 `images/worship/notices/YYYYMMDD-N.jpg`를 올리면 뷰어가 자동으로 넣는다(설정 불필요, 고정 안내만 `defaults.announcements`) ℹ️ 안내(가사 미등록·응답 문구 미입력·주제 그림 미지정)는 보고에 적는다. 확인은 `python3 -m http.server 8000` → `/presentation/worship/`(슬라이드), `/presentation/worship/book.html`(예식문). 상세는 `docs/wiki/liturgy.md` "예배 슬라이드"
6-1. **모바일 주보** (`jubo/`, 2026-11-01 추가) → 6의 `YYYYMMDD.book.json`을 그대로 쓰고, 주보에만 있는 내용을 `data/jubo/YYYYMMDD.json`에 적는다(호수 `issue`, 예배 시간, 1면 그림 `cover`(1면에서 잘라 `data/jubo/YYYYMMDD-cover.jpg`), 3면 본기도 `collect`). 인쇄된 글만 옮기고(명백한 중복 문장만 정리해 보고), 지난 주 통계·헌금 명단은 넣지 않는다. `data/jubo/index.json`의 `dates` 맨 앞에 그 주를 넣는다. **성경 본문·성가 악보·기도문은 항목 토글 안에서 화면 전환 없이 보인다.** 독서 본문은 `node scripts/extract-bible.js "묵시 7:9-17" "1요한 3:1-3" "마태 5:1-12" --write`로 `data/worship-texts/readings.json`에 넣는다(PDF 글자 + 온라인 띄어쓰기 대조, 다르면 멈춤). 본문이 없으면 공동번역 온라인 링크, 악보가 없으면 성가집 앱 링크로 대신한다. 새 성가는 `data/worship-texts/hymns.json`에 `title`·`pdfPage`를 넣는다(예배 슬라이드용). 확인: `python3 -m http.server 8000` → `/jubo/` (iPhone 390px·Galaxy 412px 폭)
   - **묵상란은 두지 않는다**(2026-11-01 사용자 지시). 2면 묵상 글은 옮기지 않고, 예배 순서·교회소식·교회 안내만 싣는다. 설교 항목은 "오늘 말씀" 한 줄만 보인다.
   - **이름은 "주보"** (상단 "광명교회 주보"). "예배 순서지"로 바꿨다가 되돌렸다(2026-11-01, 사용자 결정).
   - **주보에 인쇄된 순서만 싣는다.** 교회 슬라이드에만 있는 순서(예물 기도·두 번째 성찬기도·영성체·파송 등 `extra`)는 모바일 주보에서 자동으로 뺀다. **다음 주일 봉사자 구역은 두지 않는다**(사용자 요청). 주보 내용 정리 텍스트에는 봉사자를 계속 넣는다.
   - **본기도 항목은 사제·회중 응답("주님께서 여러분과 함께 … 기도합시다") 다음에 본기도 본문**이 온다(여정훈 사도 요청 반영, 2026-11-01).
   - **교회와 세상을 위한 기도 회중 응답**은 `data/worship-order.json`의 해당 항목 `refrain`에 입력한다. 이번 주(2026-11-01)는 사도 요청으로 `주여 우리의 기도를 들어주소서.`를 넣었다. 다음 주부터 계속 쓸지는 사용자에게 확인 전까지 지난 주 값을 그대로 가져오지 않는다.
   - **교회와 세상을 위한 기도는 기도서 1양식 전문**(`responses.json`의 `intercession-form1`)을 싣고, 이끄는 사람은 **기도자**로 표기한다(실제로 기도자가 인도하며 사제가 아니다, 2026-11-01 사용자 지적). 예식문(`presentation/worship/book.html`)도 같다. 슬라이드(`presentation/worship/`)는 응답만 쓰므로 그대로다. 대화 줄 역할은 `p` 사제 · `k` 기도자 · `l` 독서자 · `a` 회중이다.
   - **스크롤 주의:** 스크롤 중에 다른 요소를 스크롤하거나(`scrollIntoView`·탭 줄 `scrollLeft`) 화면을 흔드는 효과(`backdrop-filter`, `scroll-behavior: smooth`)를 쓰지 않는다. 아이폰에서 화면이 튕기거나 멈춘다(PR #614·#615). 탭 줄은 스크롤이 멈춘 뒤에만 움직인다.
   - **줄간격 기준(2026-11-01 검수):** 본문 줄간격 1.65(응답 줄·평문·성시), 본기도 상자 1.7. 응답 줄 사이 여백 6px, 구분 간격(`.gap`)은 `.15em`으로 좁게 둔다. 구분 간격을 크게 잡으면 "주여 우리의 기도를 들어주소서"와 사제 줄이 떨어져 한 기도로 안 읽힌다. 간격을 바꾸면 iPhone 390px 화면으로 항목을 모두 펼쳐 눈으로 확인한다.
   - **모바일 주보 배포 원칙 (2026-11-01 사용자 확정)** — 모바일 주보와 본문·성가 악보 이미지는 공개 저장소에 반영하고 GitHub Pages의 `/jubo/`에 웹 배포한다(사용자 명시 승인, 2026-11-01). 교우가 웹에서 열어 보도록 하되, 링크 안내는 비공개 교회 밴드에서만 한다. 공개 홈페이지 본문·메뉴·푸터·사이트맵·공개 게시물에는 모바일 주보 링크나 홍보를 추가하지 않는다. “홈페이지에 게시하지 않는다”는 웹 배포 금지가 아니라 홈페이지에서 연결·홍보하지 않는다는 뜻이다. 이 범위의 커밋·푸시·PR·머지는 기존 자동 처리 절차로 진행하며 공개 접근 가능성을 이유로 매번 재승인을 요청하지 않는다. 비공개 밴드에 링크를 올려도 공개 저장소/GitHub Pages의 대상 파일 자체가 비공개로 전환되지는 않는다. 원본 PDF·악보 이미지의 공개 여부와 검색 제외는 별도로 관리하고, robots.txt나 링크 숨김만으로 비공개·검색 제외가 완료됐다고 기록하지 않는다.
   - **성가 악보 원칙 (2026-11-01 사용자 확정)** — 단성판을 기본으로 사용하고 수록되지 않은 곡은 전체판에서 가져온다. 해당 곡의 악보 이미지를 그대로 기존 토글 안에 넣는다. PDF 전체 열기나 #page 링크로 대체하지 않는다. 원본 파일명은 영어로 단성판(unison)·전체판 및 분할 번호(part-01 등)를 구분하고, 문서의 자료명은 ‘성가’로 기록한다.
   - **기존 운영 기록 (2026-11-01 사용자 결정)** — 홈페이지(`bulletin.html`)의 "모바일 주보 보기" 버튼을 뺐다(`data.js` `bulletins.mobile` 삭제). 교우에게만 주소(`/jubo/`)를 알리고, 그 대신 **성가 악보 이미지(`book.json` `scores`, `data/hymnal-2015/images/`)를 토글 안에 싣는다.** 같은 날 저작권 때문에 악보를 빼고 앱 링크만 두었다가 이 결정으로 되돌렸다. 버튼을 다시 넣자고 하면 악보 공개 여부도 함께 확인한다. PDF 쪽 링크(`#page=`)는 휴대폰에서 쪽 이동이 안 되어 쓰지 않는다. `data/hymnal-2015/`(성가집 스캔)는 **삭제를 보류**한다(2026-11-01 사용자 결정: 웹페이지로 공개하는 것이 아니므로). 저장소가 공개 상태라 파일은 내려받을 수 있다는 점은 사용자도 안다. 다시 정하자고 하기 전에는 지우지 않는다.
   - **링크 점검:** `tests/juboLinks.test.js`가 성경 책 이름·시편 악보 이미지·성가 번호를 검사한다. 새 주보를 올릴 때 `npm test`가 통과해야 한다. 기도서·성가집은 외부 개인 사이트(dulkuka12.github.io)라 주소가 바뀌면 직접 확인한다.
7. `npm test` (병합·표기·overrides·교회소식·핵심구절·예배 슬라이드 형식 검증 포함)
8. **보관 규칙: 최근 8개 주보만 유지(기간 제한 없음, 2026-11-05 사용자 확정)** — 넘긴 주보의 이미지·PDF·교회소식·핵심구절은 새 주보를 올릴 때 sync가 삭제한다. 다시 필요하면 이미지를 `bulletins/`에 되돌려 놓고 sync. overrides의 과거 항목은 그대로 둬도 무방

## 교회소식 검수 기준 (작성 후 매번 스스로 점검)

0. **용어집 먼저** — `docs/church-glossary.md`(표기 기준·주보 구성·용어)를 읽고 시작한다.

1. **원문 대조** — 항목 수, 날짜·요일·시각·장소·이름·금액이 이미지와 일치하는지 한 건씩 확인한다. 흐려서 읽을 수 없는 글자는 추측하지 말고 보고에 남긴다.
2. **의미 유지** — 요약·재작성·추가 금지. 인쇄된 문장을 그대로 옮긴다.
3. **교정 허용 범위(이것만 고친다)** — 띄어쓰기(다음 주일, 둘째 주일, 교재 구입), 약어는 점 표기(`G.F.S.`), 같은 장소·행사의 표기 통일(예: 프란시스 홀), 날짜 형식 통일(`15일(목)`, `10월 17일(토)`, `오후 2시 30분`), 명백한 오탈자. **요일은 사이트가 자동으로 붙인다**(`NewsRenderer._withWeekdays`: 날짜에 요일이 없으면 보여 줄 때 `(요일)` 추가, 일요일은 `주일`). 그래서 원문에 요일이 없어도 따로 적지 않는다. 원문에 요일이 있으면 그대로 두며, 실제 요일과 다르면 `npm test`가 실패하므로 주보 오기를 확인해 바로잡는다.
4. **제외** — 지난 주일 통계, 헌금·봉헌자 명단 등 개인 이름이 나열된 란은 옮기지 않는다. 담당자 이름이 본문에 포함된 안내(예: 신청 접수 담당)는 원문대로 둔다.
5. **개수·중복** — 같은 소식이 주마다 반복돼도(예: 바자회 안내) 그 주 주보에 있으면 그대로 올린다. 한 주 안의 중복만 정리한다.
6. **형식 확인** — `node scripts/sync-bulletins.js` 후 ℹ️ 교회소식 미기록 경고가 없는지, `npm test` 통과, 로컬(`python3 -m http.server`)로 `news.html`에서 항목표 렌더와 줄바꿈을 눈으로 확인한다.

## 교회 지식 쌓기 (검수하며 스스로 배우고 잊지 않게 문서화)

- 검수 중 낯선 용어·약어·기관·장소·반복 행사·이름 표기를 만나면 사이트 데이터(`data.js`), 지난 주보, 필요하면 한글·영문 웹 검색으로 **확인된 사실만** 찾아 `docs/church-glossary.md`에 추가한다. 출처와 확인일을 적고, 확인하지 못한 것은 `미확인`으로 둔다(추측 금지).
- 사용자가 표기나 사실을 바로잡아 주면 그 자리에서 용어집에 기록하고, 같은 실수를 반복하지 않도록 필요하면 검수 기준·테스트에도 반영한다.
- 대화가 끝나면 기억이 사라지므로, 배운 것은 **반드시 문서에 남기고 같은 PR에 포함**한다. 시간이 지난 정보(공사·행사 등)는 용어집 "진행 중인 일"에서 정리한다.

> ⚠️ 병합 규칙은 `scripts/lib/lectionary.js`(스크립트·테스트용)와 `app.js`의 `_applyOverrides`(브라우저용) 두 곳에 있다 — 빌드가 없어 공유 불가. 한쪽을 고치면 반드시 다른 쪽도 함께 고칠 것.

## 모바일 주보 추가 원칙 (2026-11-01 사용자 확정)

- **기준 화면과 재사용 스킬 (2026-11-01 사용자 확정)** — https://frpsy.github.io/gmchurch_web/jubo/ 의 현재 구성을 매주 유지한다. 주보 작업 전에 [모바일 주보 스킬](.agents/skills/gmchurch-mobile-bulletin/SKILL.md)을 읽는다. 상단·탭 → 표지 → 이번 주 말씀 → 예배 순서(본문·악보·기도문 토글) → 교회소식 → 안내 순서를 따른다. 날짜·내용을 갱신하되 사용자 요청 없이 디자인을 재구성하지 않는다.

- **고령 교우의 화면 이동 최소화 (2026-11-01 사용자 확정)** — 예배 중 필요한 성경 말씀 전문·설교의 바탕 본문·기도문·성가 악보는 모바일 주보의 해당 항목 안에서 펼쳐 읽는다. 설교 항목에도 해당 성경 본문 전문을 표시한다. 실제 설교 원고 전문은 제공받은 경우에만 싣고 임의로 만들지 않는다. 악보를 눌러 새 탭·이미지 화면으로 이동시키지 않고 현재 화면에서 두 손가락 확대를 이용한다. 자료가 빠졌다고 외부 링크로 대체하지 말고 원문을 확보해 보완한다. 안내 영역의 선택적 외부 링크와 예배 중 필수 자료를 구분한다.

- **교회 맥락으로 기도문 완성 (2026-11-01 사용자 확인)** — 기도서 양식의 ‘우리 주교 ( )’ 등 교회가 채우는 빈칸은 홈페이지 ‘섬기는 이들’의 `data.js`와 교차 확인한다. 현재 서울교구장 주교는 `CHURCH_DATA.bishop.name`의 김장환(엘리야) 주교다. 모바일 주보의 ‘우리 주교’에는 이 값을 연결해 빈칸을 남기지 않으며 이름을 여러 파일에 하드코딩하지 않는다. 기도서 원본 양식은 보존하고 표시할 때 교회 정보를 적용한다. 다른 인물·직책도 해당 공식 데이터와 확인된 문맥으로 채우되, 미확인 이름·의향은 추측하지 않는다. 과거 인물·연혁을 현재 인물로 일괄 치환하지 않는다.
