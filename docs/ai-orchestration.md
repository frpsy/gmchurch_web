# AI 오케스트레이션 (ChatGPT·Gemini 보조, Claude 지휘)

> 작성 2026-11-21, 사용자 지시. 순서지(모바일 주보 `jubo/`)를 포함한 홈페이지 작업에서 외부 AI를 어떻게 쓰는지 정한다.
> 역할은 메모리 `feedback-ai-orchestration-roles`와 맞춘다. 충돌하면 이 문서가 최신이다.

## 1. 역할

| 주체 | 맡는 일 | 쓰기 권한 |
|---|---|---|
| **Claude** | 지휘, 작업 분해, 코드 수정, 테스트, 화면 확인, PR·머지, AGENTS.md 규칙 준수, 최종 판단 | 저장소 쓰기 |
| **ChatGPT** (Codex CLI, ChatGPT 로그인) | 코드·diff 독립 검토, 반론(적대적 리뷰), 주보 이미지 판독 | 읽기 전용 (`-s read-only`) |
| **Gemini** (API) | 독립 검토(접근성·한국어 문체), 주보 이미지 판독, 이미지와 데이터 대조 | 없음 (API 호출만) |

AI는 저장소에 쓰지 않는다. 파일 수정은 Claude만 한다. 머지도 Claude가 CI와 화면 확인을 마친 뒤에만 한다.

## 2. 연결 방법

- **ChatGPT**: `codex exec --skip-git-repo-check -s read-only -C <저장소> -o <출력> "<프롬프트>"`. 이미지는 `-i <파일>`.
- **Gemini**: 환경 변수 `GEMINI_API_KEY`로 호출한다. Gemini CLI의 구글 로그인은 지원 종료되어 쓰지 않는다.
  - 기본 모델은 `gemini-3.5-flash`다. 2026-11-21 확인: `gemini-3.1-pro-preview`는 할당량 429, `gemini-2.5-flash`는 신규 사용자에게 404였다. 바꾸려면 `AI_GEMINI_MODEL`을 설정한다.
  - 키는 저장소·문서·채팅에 적지 않는다. 로컬 환경 변수나 개인 설정 파일에만 둔다.
- **공통 래퍼**: `scripts/ai-call.py`
  ```bash
  python3 scripts/ai-call.py gemini  --prompt p.md --out out.md --file 대상.diff [--file 이미지.jpg]
  python3 scripts/ai-call.py chatgpt --prompt p.md --out out.md --file 대상.diff --cwd .
  ```
  Gemini는 텍스트 파일을 본문에 붙이고 이미지는 inline으로 보낸다. ChatGPT는 파일 경로를 프롬프트에 적는다.

## 3. 작업 흐름

### A. 화면 개선 (예: 접근성 보정)
1. 같은 질문을 두 모델에 보낸다. 서로의 답을 보지 못하게 한다(별도 호출).
2. Claude가 두 답을 대조한다. 같은 지적은 채택 후보, 엇갈린 지적은 코드로 직접 확인한다.
3. Claude가 최소 변경으로 구현하고 `npm test`를 돌린다.
4. diff를 ChatGPT에 보내 반론을 받는다. Gemini에도 같은 diff를 보낸다.
5. 390px·다크모드·인쇄를 확인한다(AGENTS.md 7번). 이 확인은 AI가 대신하지 않는다.
6. 확인이 끝나면 PR을 머지하고 공식 저장소에 반영한다.

### B. 주보 제작 (순서지 데이터)
1. 주보 이미지를 ChatGPT와 Gemini가 각각 읽어 예배 순서·교회소식을 옮긴다(이미지 전달 허용, 2026-11-21).
2. Claude가 `worship-order.json` 초안을 만들고 세 판본을 항목별로 대조한다.
3. 불일치는 이미지를 더 크게 잘라 다시 읽히거나 사용자께 확인한다. 이름·본문은 추측하지 않는다(AGENTS.md 5번).
4. 누락 점검은 기존 테스트(`tests/worshipCompleteness.test.js` 등)를 우선한다. AI 대조는 보조로만 쓴다.

### C. 코드 리뷰 (작은 변경)
1. diff만 보낸다. 근거(파일:줄)와 심각도를 요구한다.
2. 근거 없는 "문제 없음"은 약한 증거로 본다.

## 4. 판단 규칙

- **AI 답은 데이터다.** 줄 번호와 확인 근거가 없는 주장은 채택하지 않는다.
- **검증 책임은 Claude에 있다.** 계산(대비비 등)은 실제 값으로 다시 계산한다.
- **두 모델 합의만으로 머지하지 않는다.** 머지 조건은 테스트 통과 + 화면 확인이다.
- **디자인 고정(2026-11-05)을 따른다.** 화면 외형을 바꾸는 제안은 사용자 승인 전에 실행하지 않는다. 접근성 예외는 `docs/mobile-bulletin-rules.md`에 기록한다.
- **실패는 숨기지 않는다.** 모델이 안 되면(429·404·인증 오류) 모델을 바꾸거나 다른 주체로 대체하고, 그 사실을 보고한다. 둘 다 안 되면 확인하지 못했다고 쓴다.

## 5. 보안·개인정보

- 외부 AI에는 검토에 필요한 코드 발췌·diff·주보 이미지만 보낸다.
- 교우 개인정보(이름·연락처·헌금 내역·소그룹 명단 등)는 텍스트로도 이미지로도 보내지 않는다. 주보 이미지에 이름이 있어도 교회소식 판독 목적이면 허용한다(2026-11-21 사용자 확인).
- 키·토큰·계정 정보는 어디에도 쓰지 않는다.

## 6. 기록

- 작업 장부(ledger)는 `scratchpad`의 작업 폴더에 둔다. 저장소에는 넣지 않는다.
- 장부에는 질문, 각 모델의 답 요약, Claude가 채택·기각한 이유를 적는다.
