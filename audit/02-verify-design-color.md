## 2. 직접 측정으로 확인한 "조사팀 미확인" 항목

### 2-1. 다크 호버 글자 소실
- 라이트·다크 각 373종 호버 측정. 글자가 사라지는(≈1:1) 사례 **없음**. 1.0~1.3 값은 모두 측정 아티팩트(스크롤 reveal 전 `opacity:0` 카드, 호버 때만 보이는 `▶`·사진 오버레이)였음.
- 실제 미달은 두 가지뿐: 다크 `.about-brief-award:hover` 안의 → (`#65a183`/`#3a5947` = 2.6:1) — COL-05, 라이트 `.lectionary-ref` ↗ 2.98:1 — COL-06.
- `.btn-hero-primary:hover`(다크 9.9:1), `.btn-outline:hover`(5.06), `.press-link` 다크(4.71), `.links-card` ↗ 다크(5.41)는 통과.

- `style.css:154-158` `:focus-visible { outline:3px solid var(--theme); outline-offset:3px; border-radius:3px; }`는 특이도 0,1,0이라 자체 `border-radius`가 있는 클래스는 이기지만, radius 선언이 없는 포커스 요소(예: `summary`, 일부 링크)는 포커스 순간 모서리가 3px로 바뀜. 라운드 제어는 `a:focus-visible`/`button:focus-visible`(`:159-163`)에서 이미 outline을 정하므로 `border-radius:3px`를 삭제해도 링 형태가 요소 radius를 따라감. 이번에 렌더링으로 실제 모서리 변화를 재현하지는 않았음(코드 사실만 확인) → 수정 전 `summary`·`.faq-q`로 확인 필요.
- 위험: 낮음. 라운드 2.

## 6. 다른 분야와의 충돌 조정 제안

1. 링크 표시(타이포): 본문 링크는 "색 `--theme` + 밑줄 1px, offset 2px, 굵기 600(`.faq-a-text a`와 동일)"을 단일 기준으로 한다. 타이포 팀이 굵기를 400으로 내리려 하면 밑줄이 있으므로 문제 없음(색 단독 구분 의존 해제).
2. 달력 지난 날짜(COL-02) vs 타이포(달력 숫자 12.5px/라벨 9.9px 확대 제안): 색은 `--text-muted`로 바꾸고 크기 변경은 타이포 라운드 3에서. 같은 선택자(`.lit-cal-num`, `.lit-cal-label`)를 두 라운드가 건드리므로 라운드 2에서 색만, 3에서 크기만 수정해 충돌을 피한다.
3. 포커스 링 오프셋(디자인) vs 레이아웃(내비 높이 68px): 드롭다운은 `offset:-3px`(안쪽)로 두어 레이아웃 영향 없음. 최상위 `.nav-link`는 높이 100%라 offset 4px 링이 막대 밖으로 나가 위가 잘림(스크린샷 `sheet_light.png` nav에서 상단 클리핑) → 레이아웃 팀이 내비 높이를 건드리면 offset을 `-4px`로 바꾸는 방식으로 대응. 이 수정은 DES 쪽 후보(보류, 이번 라운드에서는 육안상 허용).
4. 간격 토큰(레이아웃)과 카드 패딩(DES-08): 카드 패딩은 `--space-5`(1.5rem)·`--space-6`(2rem)·`--space-7`(2.5rem) 3단계 토큰으로 레이아웃 팀이 정한 값을 따른다. 이번 검증에서는 카드 패딩을 임의 변경하지 않음.
5. 인라인 `font-size`(DES-05)는 타이포(3), 인라인 `margin/display`(DES-05)는 컴포넌트(5)로 분담.

### 7-3. 버튼·카드 규격 제안
- 버튼 공용 베이스 `.btn`(실측 값 기반, 가장 많이 쓰이는 `btn-next` 기준으로 흡수):
  - 패딩 `var(--space-3)` ~ `.85rem` 세로 / `1.7rem` 가로(현 `btn-next` 13.6/27.2px와 동일), 최소 높이 44px(터치), 글자 `--fs-sm`(14.4px) 굵기 600
  - radius: 주 CTA·필터·칩은 `--radius-pill`(999px), 히어로 흰 버튼·지도 버튼·더보기 같은 "네모형" 컨트롤은 `--radius-sm`(8px). 한 화면 안에서 같은 위계의 버튼은 같은 radius.
  - 소형 칩(`bus-chip`, `map-copy-btn`): `--radius-xs: 4px`(신규), 패딩 `.2rem .55rem` 유지.
  - 그림자: 정지 상태 없음, hover `translateY(var(--lift-1))` + `--shadow-md`. 라이브 버튼만 `--red-hover` 그림자.
  - 변형: `--primary`(`--theme` 면), `--ghost`(테두리), `--on-dark`(흰/크림 면), `--live`(빨강).
- 카드 공용 규격:
  - radius `--radius-md`(14px); 인물·주교·영상 카드는 `--radius-lg`(20px).
  - 패딩: 소형 정보 카드 `--space-5`(1.5rem) / 표준 카드 `--space-6`~`--space-7`(2~2.5rem, 현 `card`·`info-card` 40/36px 포함) — 현 실측 값 40/36, 28/24, 25.6/22.4, 19.2/22.4를 이 3단계로 수렴하는 것은 라운드 5에서 화면별 확인 후.
  - 테두리 `1px solid var(--border)`, 강조 띠는 왼쪽(4px) 또는 위(3px) 한 방향만.
  - 그림자: 정지 `--shadow-sm`(모든 카드가 아니라 `faq-item`·인물 카드처럼 겹침이 필요한 곳만), hover `translateY(var(--lift-2)=-4px)` + `--hover-shadow-sm`(큰 카드도 같은 값; `--hover-shadow`는 `.card` 하나만 쓰므로 정리 대상).
  - 신규 토큰: `--radius-xs:4px`, `--lift-1:-2px`, `--lift-2:-4px`.

### 7-4. 포커스 링 규칙 제안
1. 기본: `outline: 2px solid var(--theme); outline-offset: 2px`(현 3px/3px에서 두께 3→2px로 줄이지 말고 현행 3px 유지해도 무방, 필수는 색 규칙). 라이트 7.94:1, 다크 5.41:1.
2. 어두운 숲 녹 면 위(내비 막대·푸터·히어로·`next-step-cta`): `outline-color: var(--gold)`(라이트 6.21, 다크 9.25). 예외로 흰색 바탕인 곳(드롭다운, 고정 흰색 서브 내비)은 기본 `--theme`.
3. 사진 위 요소와 라이트박스: 흰색 `#fff` 2px(필요 시 `box-shadow: 0 0 0 4px rgba(0,0,0,.35)` 이중 링). 측정상 히어로 버튼의 세이지 링은 최소 3.08이라 흰색이 더 안전하지만 현행도 통과.
4. 링을 제거해도 되는 경우는 없음. hover와 같은 배경색 변화만으로 대체 금지 → `outline:none` 선언은 `:focus:not(:focus-visible)` 외에는 사용하지 않는다. (현재 위반 7곳: DES-03, DES-04 6곳.)
5. 오프셋: 원형·작은 컨트롤 2px, 막대에 꽉 찬 요소(드롭다운·서브내비)는 `-3px`(안쪽), 이동하는 카드(`photo-item`)는 2px로 카드 바깥.
6. 검증 방법: 새 컴포넌트는 Tab 순회로 링 바깥 픽셀 대비 3:1 이상을 `focus.py`로 확인(라이트·다크 1440/390).
