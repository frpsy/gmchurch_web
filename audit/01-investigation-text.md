- 분류: (1) 수정 가능 / (2) 확인 필요 / (3) 줄바꿈·CSS

## 1. 개요

### 방법
1. `CLAUDE.md`, `docs/church-glossary.md`, `docs/wiki/README.md`, `audit/00-page-inventory.md`를 읽고 표기 기준과 "의미 변경 금지" 범위를 확인했다.
2. Playwright(Chromium, 헤드리스)로 20개 페이지를 360px 기준으로 렌더링하고 `document.body.innerText`를 추출해 읽었다. `<details>`는 펼친 상태로도 추출했다(FAQ, 주요 이력, 캔터베리 십자가).
3. 문자 단위 `Range.getClientRects()`로 360/390/768px(단어 중간 끊김 검사)와 360/390/768/1440px(마지막 줄 고아 검사, 가로 넘침 검사)를 20페이지 전부에 대해 측정했다.
4. 지적 위치는 `grep -n`과 Grep/Read로 확인한 줄번호만 적었다. 렌더 결과에서만 보인 것은 선택자로 적었다.
5. 맞춤법 근거는 한글 맞춤법·문장부호 규정, 표준국어대사전, 외래어 표기법 용례다. 실제 사전 조회로 확인하지 못한 것은 "미확인"으로 표시했다. 이번 세션에서는 WebSearch를 호출하지 않았다.
6. 인명, 직함, 전례 용어, 성경 표기, 날짜, 시간, 주소, 전화, 계좌, 기관명은 고칠 대상으로 올리지 않고 "확인 필요"로 분류했다.

### 범위와 한계
- 대상: 20개 HTML 페이지의 렌더 결과, `data.js`, `app.js`의 UI 문구, `data/bulletin-news.json`, 정적 HTML 본문.
- 제외: `data/lectionary-*.json`의 성경 구절 데이터는 전수 검토하지 않았다(미확인 항목 참조).
- 스크린샷(`audit/screenshots/baseline`)은 직접 보지 않고 위 측정 결과를 썼다. 지적한 고아 줄 5곳은 요소 단위 캡처로 눈으로 확인했다(홈 푸터 주소 1440px, 예배 `h3` 360px 등).
- 렌더링 환경은 서버 Chromium과 Pretendard 웹폰트다. 실제 iOS Safari와 안드로이드는 미확인이다.

### 핵심 결과
- 한글 단어 중간 끊김은 **0건**이다. `body`에 `word-break: keep-all; overflow-wrap: break-word`가 적용돼 있고(`style.css:110-111`), `break-all`은 어디에도 없다.
- 가로 넘침(요소 `scrollWidth > clientWidth`)도 **0건**이다.
- 고아 줄(마지막 줄에 1~2글자)은 제목 계열과 홈 푸터 주소에서 발견했다. 원인은 제목에 `text-wrap: balance`가 없는 것이다.
- 본문 오류 중 가장 눈에 띄는 것은 `greenchurch.html:418`의 마크다운 별표 노출이다. 렌더 화면에 `*Animal Theology*`가 그대로 보인다.
- 사이트 내 모순 정보로 이남호 사제의 입학 나이(35세 vs 37세), 비건 애찬 설명, 환경주일 날짜, 고요한/찰스 존 코프 표기가 있다.

## 4. 미확인 항목

- 표준국어대사전과 국립국어원 자료를 이번 세션에서 직접 조회하지 못했다. TXT-03(첫날), TXT-06(4주분), TXT-36·37(외래어 표기)은 기억에 근거한 판단이며, 조회 후 확정해야 한다.
- 성경 구절 데이터(`data/lectionary-year-a.json`, `-b.json`, `lectionary-overrides.json`)의 책 이름과 장절 표기는 전수 검토하지 않았다.
- 주보 이미지(`bulletins/*.jpg`)와 소식 문구의 원문 대조는 하지 않았다. TXT-15, TXT-30, TXT-31은 원문 확인이 필요하다.
- `images/` 안에서 Unsplash 이미지 사용 여부, `data.js:783`(`liveUrl`)이 어디서 쓰이는지는 확인하지 못했다(TXT-40).
- 실제 iOS Safari·안드로이드 기기와 다른 폰트 환경에서의 줄바꿈은 확인하지 못했다. `text-wrap: balance`와 `text-wrap: pretty`는 브라우저 지원이 다르다(미지원 시 무시되며 레이아웃이 깨지지는 않음).
- 다크모드·인쇄 스타일에서의 줄바꿈 차이는 측정하지 않았다.
- 1024px 폭은 단어 끊김·고아 측정에 포함하지 않았다(360/390/768/1440만 측정).
