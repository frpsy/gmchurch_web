# 순서지 제작 (실행 절차)

"순서지"는 모바일 주보(`jubo/`)를 줄여 부르는 말이다(2026-11-05). 페이지 이름은 "주보"로 유지한다. 이 문서는 실행 순서와 상시 규칙의 요약이다. 상세 근거는 아래 문서를 먼저 읽는다.

## 먼저 읽을 것
1. `AGENTS.md` "주보 요점"
2. `docs/mobile-bulletin-rules.md`(운영 원칙, 우선) → `docs/bulletin-procedure.md` 6-1 → `.agents/skills/gmchurch-mobile-bulletin/SKILL.md`(화면 구성·모바일 확인)
3. 사용자 후속 지시가 문서보다 우선한다. 규칙이 바뀌면 같은 작업에서 위 문서와 이 스킬도 함께 고친다.

## 요청어
- 주보 이미지만 오면 묻지 않고 한 세트로 진행한다: 홈페이지 주보 게시(`bulletin.html`) + 순서지 제작 + 주보 내용 텍스트 정리. 예배 슬라이드는 요청이 없으면 만들지 않는다.
- `주보제작`: 제작·검수·두 저장소 배포·링크 보고까지.
- `주보검수`: 점검과 보고만. 게시·수정은 하지 않는다.

## 제작 순서
1. **주보 읽기**: 예배 순서와 교회소식을 인쇄된 값 그대로 옮긴다. 이름과 본문은 추측하지 않는다. 위키·`data.js`로 확인하고, 읽기 어려운 글자는 보고에 남긴다.
2. **예배 순서**: `data/worship-order.json`에 그 주 항목을 넣고 `node scripts/build-worship-slides.js`를 실행해 `data/worship/YYYYMMDD.book.json`을 만든다.
3. **순서지 데이터**: `data/jubo/YYYYMMDD.json`에 호수·날짜·표지 그림·예배 시간을 적는다. `data/jubo/index.json`의 `dates` 맨 앞에 새 날짜를 넣는다. 표지 그림은 1면 사진에서 잘라 `data/jubo/YYYYMMDD-cover.jpg`로 둔다.
4. **독서 본문**: `node scripts/extract-bible.js "<구절>" --write`로 `data/worship-texts/readings.json`에 넣는다. 쉼표로 이은 구절은 `에제키엘 34:11-16,20-24`처럼 공백 없이 쓴다.
5. **성시**: 비우지 않는다. `node scripts/extract-psalm.js <편> --write`로 본문을 뽑고, `lines`를 `worship-order.json`에 넣는다(1~6절 + 영광송). PDF 절 번호가 빠지면(예: 100편은 5절로 나온다) 인쇄된 주보의 절 번호를 따른다. 악보는 주보 3면에서 잘라 `data/worship/scores/YYYYMMDD-psalm.png`로 연결한다.
6. **성가**: `data/hymnal-2015/` 악보를 단성판 우선으로 쓴다. 번호만 넣으면 악보가 연결된다. `worship-texts/hymns.json`에 없는 곡은 `title`과 `pdfPage`(악보 이미지 쪽 번호와 같음)를 추가한다. `book.json` 생성 뒤 `node scripts/hymnal-web-exclude.js`를 실행한다.
7. **교회소식과 핵심구절**: `data/bulletin-news.json`·`data/bulletin-verses.json`을 채운다. 교회소식은 인쇄된 글과 줄 단위로 대조해 빠진 줄이 없게 한다. 교회소식 마지막 항목은 「애찬」 칸의 그 주 이름이다(아래 상시 규칙).
8. **주보 게시판**: 주보 이미지를 `bulletins/YYYYMMDD_N.jpg`(표지부터 순서대로)로 두고 `node scripts/sync-bulletins.js`를 실행한다. 최근 8개만 유지한다.
9. **검증**: `npm test`가 통과해야 한다. 브랜치 → 커밋(한국어 메시지, `git add -A` 금지, 파일 지정) → PR → CI 확인 → squash 머지까지 묻지 않고 끝낸다.
10. **공식 반영**: 개발 머지 뒤 같은 작업 안에서 `scripts/release-official.sh` → 공식 PR → squash 머지. 주보·교회소식 포함 두 곳 모두 반영한다.

## 상시 규칙 (사용자 확정)
- **인쇄 기준**: 주보에 인쇄된 값을 따른다. 기도서 쪽 번호와 봉사자 이름 모두 해당한다. 인쇄된 쪽이 `bcp.json`에 없으면 그 쪽 키를 추가한다(2026-11-22 성체나눔 269쪽).
- **애찬 준비(2026-11-15, 2026-11-22)**: 교회소식 마지막 항목은 `{ "title": "이번 주 애찬 준비", "body": "이름" }`이다. 이름은 봉사자표 「애찬」 칸에서 그 주 날짜 줄을 찾아 쓴다. 이번 주 줄이 없으면 지난 주 주보의 봉사자표를 확인한다(2026-11-22는 11/15 주보의 11/22 줄에서 찾았다).
- **회중 응답(`refrain`)**: 교회와 세상을 위한 기도의 회중 응답은 주마다 확인한다. 확인이 없으면 최근 주보의 사용값을 쓰고 보고한다(2026-11-22 "주여, 우리의 기도를 들어주소서.").
- **온 가족 예배 예식문(2026-11-15)**: 따로 받은 예식문 PDF가 있으면 순서·봉사자는 주보대로, 글은 예식문대로 `type: "text"` 항목에 적는다. 찬양 악보는 PDF에서 뽑아 `data/worship/scores/`에 두고, 기도문 사이 악보는 `lines`의 `{img}` 줄로 넣는다(상세 `docs/bulletin-procedure.md` 6-1).
- **복음성가 묶음(2026-11-14)**: 받은 묶음 PDF는 `data/hymnal-2015/sources/praise/`에 저장만 하고 README에 기록한다. 웹에 올리지 않고, 연주 지시는 싣지 않는다.
- **디자인 고정(2026-11-05)**: 데이터만 바꾼다. 레이아웃·색·버튼·문구 요소를 바꾸지 않는다. 홈페이지에서 순서지로 링크하지 않는다.
- **인쇄 고려 안 함(2026-11-22)**: 순서지는 휴대폰 화면 전용이다.
- **주보에 인쇄된 순서만** 싣는다(`extra` 제외). 다음 주 봉사자 구역과 묵상란은 두지 않는다.
- **텍스트 최우선(2026-11-08)**: 악보가 틀려도 성시·독서 등 본문 텍스트는 비우지 않는다. 악보 불일치는 보고에만 적는다.
- **성시는 회중 강조 없이 내용만(2026-11-08)**: ○·◉·굵은 글씨 없이 절 번호와 본문만. 데이터의 `mark`는 슬라이드용이라 지우지 않는다.
- **성가는 악보가 있으면 가사를 넣지 않는다(2026-11-08)**: 악보 이미지만 보인다. 악보가 없을 때만 텍스트로 보완한다.
- **설교 란에는 성경 본문을 넣지 않는다(2026-11-08)**: 복음 본문은 복음 항목에만 싣는다.
- **펼침 기본값(2026-11-08)**: 성서 본문(독서·복음)만 접고, 나머지(성가 악보·성시·기도문)는 펼친다. 상단 버튼은 「전부 접기」 ↔ 「기본대로 펼치기」.
- **본기도(2026-11-22 사용자 지시)**: 본기도는 기도자가 읽으므로 본문을 순서지에 싣지 않는다. 사제·회중 응답은 싣는다. 이 적용 범위는 이번 주로 보며, 다른 주에 적용할지는 사용자에게 확인한다.
- **교회와 세상을 위한 기도**: 기도서 1양식 전문을 쓰고, 이끄는 사람은 "기도자"로 표기한다.
- **문체**: 정중·담백하게 쓴다. 하느님·감사성찬례 등 표기와 성서 책 이름은 공동번역을 따른다.
- **외부 링크로 대체하지 않는다**: 자료가 빠지면 원문을 확보해서 보완한다.

## 기도서·성가·성서 출처 (2026-11-22 사용자 확정)
- **기도서 본문 출처**: `data/worship-texts/bcp.json`에 쪽마다 기록된 출처만 쓴다. 교회 예배 슬라이드(`TalkFile_YYYYMMDD 슬라이드 N`, 대부분) 또는 온라인 기도서 `dulkuka12.github.io/kbcp/ucharist-form1.html`이다. 온라인 기도서는 개인 운영 사이트라 교회 공식 자료가 아니다.
- **대조**: 주보 제작 때 `bcp.json`·`responses.json`의 기도서 줄을 온라인 기도서와 줄 단위로 대조한다. 일치 여부만 확인하고 본문은 옮겨 적지 않는다. 불일치는 줄 수와 위치만 보고하고, 사용자가 정한다.
- **예식문 PDF**: 따로 받은 예식문이 있으면 그 글을 따른다.
- **출처 없는 본문**: 추측하지 않고 비워 두고 보고한다(예: 특정문 본기도).
- **인물 빈칸**: 「우리 주교」 등은 `data.js`의 `섬기는 이들`에서 채운다.
- **성서·성가 출처**: 성서는 `bible/` 공동번역 PDF를 `extract-bible.js`·`extract-psalm.js`로 뽑는다. 성가 악보는 `data/hymnal-2015/`를 쓴다.

## 성가 악보 옆 찬송 제거 (2026-11-22 사용자 지시)
- 성가 악보 쪽에 옆 찬송이 함께 찍혀 있으면 해당 곡 부분만 남기고 잘라낸다. 화면에서 다른 찬송 번호가 보이면 안 된다.
- 확인: 각 성가 번호가 쓰는 `hymnal-2015/images` 쪽을 열어 본다. 쪽에 여러 곡이 있으면 잘라낸다. 쪽 하나에 한 곡만 있으면 그대로 둔다.
- 잘라낸 뒤 `manifest.json`의 해당 쪽 해시·크기·`imageBytes`를 갱신한다. 원본은 git 이력에 있다.
- 실제 사례(2026-11-22): 65장 쪽에 앞뒤 찬송(64장·66장)이 섞여 있었다.

## 성가 악보 검은 테두리 (2026-11-22 사용자 지시)
- 순서지에 쓰는 악보 이미지(`hymnal-2015/images`, `unison-images`, `worship/scores`)는 가장자리의 검은 스캔 띠를 자른다. 가장자리 밝기 평균이 100 미만인 줄을 안쪽으로 잘라내고(한도 12, 남으면 60), 악보 내용은 건드리지 않는다. 처리 뒤 가장자리 밝기가 정상인지 확인한다.
- 원본 스캔(`hymnal-2015/images`)을 자르면 `manifest.json`의 해당 쪽 해시·크기와 `imageBytes`를 새 파일 기준으로 갱신한다. 그렇지 않으면 `tests/hymnalImages.test.js`가 실패한다.

## AI 협업 검수 (2026-11-22 사용자 승인)
- **목적**: 인쇄된 주보 3면과 `worship-order.json`의 항목 이름·순서·성가 번호·독서 참조·쪽 번호·담당자 이름을 대조한다.
- **보내는 것**: 교회가 인쇄한 주보 이미지와 우리 순서 데이터만 보낸다. 기도서 본문은 보내지 않는다.
- **실행**: `~/.claude/ai-collab/ai-ask.sh -t vision -i <주보 3면 이미지> -f <검수 지시문> -e low` 로 시각 판독을 맡긴다. 검수 지시문은 불일치만 `항목 | 주보 값 | 데이터 값` 형식으로 최대 10줄 보고하게 한다.
- **판정**: AI 결과는 데이터로 본다. 주보 이미지를 직접 확대해서 확인한 뒤 고친다. 예물 기도·성찬기도·영성체·파송처럼 주보에 인쇄되지 않는 `extra` 항목은 정상이다.
- **실제 발견 사례(2026-11-22)**: 성체나눔과 하느님의 어린양의 순서가 바뀌어 있었다(인쇄본: 성체나눔 → 하느님의 어린양). 제2독서 담당자 "장순희"를 AI가 "장춘희"로 잘못 읽었다. 직접 확대해서 "장순희"가 맞음을 확인했다.

## 본기도 구조 (2026-11-22 사용자 확인, 기도서 사진 기준)
- 본기도 항목은 기도서 쪽의 순서를 따른다: 사제 인사 → 집전자 "기도합시다" → 본기도(기도자가 읽음) → 회중 응답(아멘).
- 기도서 본문은 저장소에 옮겨 적지 않는다. 쪽 번호와 순서 구조만 기록한다. 본문 대조는 온라인 기도서와 줄 단위로만 한다.
- 순서지에는 본기도 본문을 싣지 않고, 사제·회중 응답만 싣는다(위 상시 규칙).

## 제작 후 누락 점검 (매번)
- 순서지의 성시·기도서 쪽·성가·성서 본문이 빠지지 않았는지 확인한다. 본문은 저장소에 있다(`data/worship-texts/`, `bible/`, `data/hymnal-2015/`).
- 새 기도서 쪽은 `bcp.json`에 추가하고, `worship-order`에는 `type: bcp`로 쓴다.
- `tests/worshipCompleteness.test.js`·`tests/psalms.test.js`·`tests/juboLinks.test.js`·`tests/hymnalImages.test.js`가 통과해야 한다.
- 화면을 바꿨다면 390px·412px, 라이트·다크에서 모든 항목을 펼쳐 확인한다. 스크롤 중 `scrollIntoView`·`scrollLeft`, `backdrop-filter`, `scroll-behavior: smooth`는 쓰지 않는다.

## 공식 반영 주기 (2026-11-22 공식 담당자 안내)
- 평소 최대 2시간. 주일 오전 10시~11시 사이에는 10분 간격이고, 11시 이후에는 평소 주기로 돌아간다.
- 공식 반영 전에는 완료라고 쓰지 않는다. 반영 지연 시간을 명시한다.
